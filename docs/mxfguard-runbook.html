Рунбук чистого переносу

Шість фаз, які розділяють три різні питання: чи файл доїхав, чи він був цілим до того, як його чіпали, і чи не переїхала разом із ним причина, через яку .mxf колись стали нечитабельними.

0 / 0
Спершу прочитати, потім форматувати

Дві речі, які неможливо відкотити

EFS. Якщо файли шифрувала вбудована в Windows EFS, ключ живе в профілі користувача. Переставили ОС — профіль зник — дані втрачені математично, і жоден інструмент у цьому рунбуці їх не поверне. Перевірка займає 30 секунд.

Артефакти інциденту. Якщо .mxf зіпсував шифрувальник, форматування системного диска знищує точку входу, персистенцію і журнали. Після цього питання «як воно зайшло» лишиться без відповіді назавжди — і зайде вдруге.

PowerShell · на кожній машині до переставленняобов'язково
# чи є EFS-шифрування на медіа-каталозі
cipher /c "D:\Media\*.mxf"

# ключі відновлення BitLocker — виписати або зберегти в AD
manage-bde -protectors -get C:

# особисті сертифікати; EFS-сертифікат експортувати з приватним ключем:
# certmgr.msc -> Personal -> Certificates -> Export -> Yes, export the private key -> .pfx
certutil -user -store My
Фаза 1

Заморозити доказ

Робиться один раз на парк, до будь-якого копіювання. Пропускається тільки якщо інцидент уже закритий і причина відома.

Скільки з MXF рятується

Режим --ransomware шукає у голові файлу перший неушкоджений MXF Partition Pack — 13-байтовий ключ 06 0E 2B 34 02 05 01 01 0D 01 02 01 01, спільний для Header, Body, Footer і Random Index Pack. Якщо він знайшовся на зсуві 7,8 МБ, значить зашифровані тільки перші мегабайти, і есенцію за цим зсувом можна діставати.

оцінка масштабу шкоди по карантинуфаза 1
python mxfguard.py scan --root Q:\quarantine --out q.csv \
    --checks magic,entropy --ransomware --hash sha256

# у стовпці salvage_offset — зсув першого цілого Partition Pack
# статус PARTIAL_ENCRYPTED = голова мертва, тіло живе
# статус ENCRYPTED         = мертвий увесь
Фаза 2

Маніфест джерела

Знімок «як було» — єдине, з чим потім є що звіряти. Без нього перевірка після копіювання не має точки відліку.

джерело · швидкий прохідhash + magic + entropy
pip install xxhash                     # опційно, але дає ×10 до швидкості

python mxfguard.py scan --root D:\Media --out C:\audit\src.csv \
    --checks hash,magic,entropy --hash xxh128 --jobs 8

Який хеш брати

Ти захищаєшся від битого кабелю, збійного контролера і bit rot, а не від зловмисника, який підбирає колізію. Криптостійкість тут не потрібна — потрібна пропускна здатність. Заміри нижче зроблено на одному ядрі тестового контейнера; на реальному залізі числа інші, але співвідношення тримається.

АлгоритмМБ/с (1 ядро)Коли брати
xxh1284813За замовчуванням. Упирається в диск, а не в CPU
blake2b551Автоматичний запасний варіант, якщо модуля xxhash немає
sha256353Коли маніфест іде в акт, аудит або юридичну площину
Фаза 3

Копіювання

mxfguard тут не бере участі. Копіює той інструмент, якому ти довіряєш — важливо лише знати, що саме він перевіряє, а що ні.

ІнструментВерифікаціяКоментар
robocopyнемає/v — це verbose, не verify. Чудовий копіювальник із нульовим контролем вмісту
rsync -aHAXвбудованаЗвіряє контрольну суму кожного переданого файлу; --checksum-choice=xxh128 у 3.2+
FastCopyє (xxHash)Найшвидший під Windows, портативний, вмикається галочкою Verify
TeraCopyє (CRC32…BLAKE3)Вміє експортувати й перевіряти зовнішній хеш-лист

Фаза 4

Звірка переносу

Питання цієї фази рівно одне: чи те саме лежить на приймачі, що лежало на джерелі. Про якість вмісту тут ще не йдеться.

приймач · тільки хеші, швидкофаза 4
python mxfguard.py scan --root E:\Media --out C:\audit\dst.csv \
    --checks hash --hash xxh128 --jobs 8

python mxfguard.py compare --src C:\audit\src.csv --dst C:\audit\dst.csv \
    --out C:\audit\diff.csv
# код виходу 1 = є HASH_MISMATCH / SIZE_MISMATCH / MISSING
# зручно вішати на нього умову в bat/ps1-обгортці
СтатусЩо сталосяДія
MISSINGЄ на джерелі, немає на приймачіКопіювати повторно; перевірити фільтри й довжину шляху > 260 символів
HASH_MISMATCHРозмір той самий, вміст іншийКопіювати повторно і перевірити носій — це вже сигнал про залізо
SIZE_MISMATCHОбрив копіюванняКопіювати повторно

Фаза 5

Контентна валідація

Тут відповідь на «чи це точно той файл». Хеш каже, що файл не змінився під час переносу — і чесно переносить пошифроване сміття зі статусом OK. Ця фаза дивиться всередину.

приймач · повний прохіддовго, ставиться на ніч
python mxfguard.py scan --root E:\Media --out C:\audit\dst_full.csv \
    --checks hash,magic,entropy,struct,decode \
    --ransomware --jobs 8 --decode-jobs 3 --resume

python mxfguard.py report --scan C:\audit\dst_full.csv \
    --compare C:\audit\diff.csv --out C:\audit\report.html

--resume дописує в наявний CSV, пропускаючи вже оброблені шляхи — прогін на десятки ТБ можна ставити на ніч і спокійно переривати. --decode-jobs тримається окремо від --jobs, бо ffmpeg упирається в CPU, а хешування — в диск.

Чотири рівні, від мілісекунд до годин

Чого mxfguard не робить

Щоб звіт зі суцільними OK не читався як гарантія, якої він не дає.

Не робитьНаслідок для тебе

Ентропія — евристика, не доказСтиснуті за природою формати (zip, jpg, mp4) виключені з перевірки саме тому; поріг --entropy-threshold регулюється

Не оцінює якість зображенняФайл, що декодується без помилок, але з чорним кадром замість сюжету, пройде як OK
Не замінює бекапЦе вимірювальний прилад. Він каже, що зламалось, а не повертає зламане
